  Adds a `test-cases.md` for each of modules 02 to 10, derived from each
  module's `spec.md` and the 12 acceptance scenarios in `REQUIREMENTS.md`. They
  give every module a reviewable list of expected behaviour before it is
  implemented. 01-core already has its own doc.

  ## Changes
  - `modules/02-parser/test-cases.md`: guards, header, item formats,
  owner/task/due splitting, sample folder.
  - `modules/03-dates/test-cases.md`: `parseMeetingDate`, `resolveDue`,
  `isOverdue`, including year rollover, invalid dates and timezone independence.
  - `modules/04-owners/test-cases.md`: the rule order, the `knownPeople`
  fallback, `Everyone`, ambiguity and `loadPeople`.
  - `modules/05-dedupe/test-cases.md`: `normaliseTask`, Jaccard `similarity`,
  `findMatch` and `mergeInto`, plus the threshold tuning step.
  - `modules/06-ingest/test-cases.md`: folder handling, item creation, merging,
  idempotency, store failures and the report format.
  - `modules/07-list/test-cases.md`: filters, sorting and output format, using a
  fixed fixture store.
  - `modules/08-done/test-cases.md`: argument validation, not-found, marking
  done and already-done.
  - `modules/09-followup/test-cases.md`: owner resolution, ordering, email
  content, the payload file and the Gmail hand-off.
  - `modules/10-cli/test-cases.md`: help, global options, exit codes, error
  output, build, README and the 12 end-to-end scenarios.

  ## Notes on status values
  - Each case has an ID, input, expected result and a status.
  - 02-parser cases already covered by `tests/parser/parseNote.test.ts` are
  marked `Auto`. The rest are `GAP`.
  - Every case in modules 03 to 10 is `GAP`, because those modules are not
  implemented yet.
  - Two cases that need Claude to create the Gmail draft are marked `manual`:
  `GH-06` in 09-followup and `E2E-10` in 10-cli.
  - Where a spec is silent, the case says "decide and document" instead of
  assuming. Examples:
    - the footer wording for one item;
    - whether `filesSeen` counts ignored files;
    - whether `N open` in the follow-up subject includes overdue items;
    - how `EOD tomorrow` and `end of next week` should resolve.

  ## Testing
  - Docs only. `npm run typecheck` was clean and `npm test` passed 5 files, 75
  tests.
  - Expected values (for example the weekday arithmetic and the list sort order)
  were worked out by hand from the specs, not run against code.

  ## Notes for reviewers
  - Please check the "decide and document" cases, since they are the places
  where the specs need a decision before the module is built.
  - As each module is implemented, its `GAP` rows should flip to `Auto` with the
  test file named.
